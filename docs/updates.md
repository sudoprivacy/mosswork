# mosswork 更新说明

[English](updates_EN.md)

mosswork 由管理员从本仓库源码构建和升级。配置更新用于刷新权限、模型授权和功能配置；软件升级用于更新服务器、客户端界面及工具环境。

## 日常权限与功能配置

管理员保存员工角色、权限或策略后，系统自动通知对应员工。模型授权及其他功能配置保存后，可在左侧“管理 → 应用设置”中切换到“应用更新”标签，在“员工客户端配置更新”区域填写说明并发布通知。

员工收到“企业配置有更新”后，在没有任务执行或准备、等待工具审批、编辑本机消息、上传附件、未发送附件或排队消息、录音或转写、浏览器录制或回放时点击“更新配置”。应用刷新当前界面，保留站点登录状态和已保存草稿，无需退出客户端。服务器始终按最新权限校验请求，延后刷新不会继续保有已撤销的权限。手动隐藏的菜单不会因新增授权而强制显示。

这条通道适用于已经安装了配置刷新功能的客户端，且只应用当前代码已支持的权限、模型授权和功能配置。通知不会替管理员保存配置，也不会启用尚未部署的新功能；详情见[配置更新](client-config-update.md)。

## 服务器软件升级

当前采用管理员手动升级：

1. 阅读本项目目标发行的版本、兼容要求及数据库迁移说明，确认客户端是否也需要更新。
2. 等待任务结束，在维护窗口完成主库、通信库、文件、密钥和隔离工作区的完整备份，并验证可恢复。
3. 从目标源码构建新的基础应用、企业应用和通信镜像，使用独立标签或 digest，保留旧镜像与配置。
4. 停止应用与通信，运行新通信镜像的迁移命令，再启动新服务；主库迁移由应用启动执行。
5. 检查 readiness、登录、模型请求、消息附件和客户端本机任务，再恢复日常使用。

具体命令与回退条件见[企业部署与恢复](../docker/enterprise/README.md#升级与回退)。升级不运行 `prepare.sh`，不重新执行 `mosswork init`，不更换已有通信密钥。产品内“系统备份”不等于企业全部组件备份。

网页用户刷新后可加载服务器已部署的新网页代码。员工客户端界面随安装包内置，单独更新服务器不会替换它的页面资源；客户端兼容要求见目标版本的发行说明。

## 员工客户端软件升级

包含自动更新功能的正式版企业客户端会在已设置服务端地址时，于启动后及每六小时通过当前服务端检查更新。登录后点击账号菜单中的“关于 mosswork / 客户端更新”，即可查看客户端版本、系统架构和更新服务端，并手动检查更新；普通员工无需服务器更新管理权限。系统托盘的桌面设置中也有相同入口，登录前同样可用。

发现新版后，点击“下载更新”；下载完成并通过 SHA-256 校验后，先保存未发送的编辑内容，再点击“重启并安装”并确认。检查和下载不会退出客户端。若本地任务仍在执行、等待审批、结果待核对或尚未同步，客户端会拒绝重启，并保留已下载的更新，待任务处理完成后再安装。

更新会整体替换客户端及其内置界面、原生桥接和匹配的 Python/文档/FFmpeg 工具环境；账号配置、项目工作目录和已有任务回执保留。Mac 请先将应用移入有写入权限的“应用程序”文件夹，不要在只读安装镜像中执行更新。当前正式自动更新目标为 macOS 13+ ARM64 和 Windows x64，按实际目标选择产物。

未包含更新器的旧客户端需要先手动安装一次带自动更新功能的正式版。离线环境仍可使用对应平台的完整安装包。

发布者需要一起构建网页、桌面壳和匹配的离线工具 payload，并公布系统架构、校验值、签名与实机验证状态，见[桌面构建](../desktop/README.md)（English）。不支持用“更新配置”下发新的界面代码或原生程序。

本机项目保存在员工工作目录；安装与升级前仍应保留该目录、原有账号配置和任务回执。跨设备查看历史不会自动复制项目或接管运行中的任务。

## 更新来源

客户端只向当前连接的服务端请求更新清单和完整更新包。服务端从本仓库官方 COS 稳定渠道取得清单并流式转发更新包，不将客户端重定向到 COS；服务端需能访问官方发行源。校验与下载绑定检查时选中的服务端和不可变发行目录，切换服务端不会改变已选更新的下载来源。服务端需部署支持 `/api/update/desktop/` 的版本，并允许反向代理长时间传输完整更新包；旧服务端不支持此接口时，可手动安装完整客户端。

客户端版本是本机安装包的版本，不代表服务端版本。服务器与 Python 包升级仍由管理员管理，`mosswork update` 与服务器在线自更新 API 保持禁用。上游同名 PyPI 包和个人版安装包不能用于企业版升级。

官方更新清单和更新包由 mosswork 发行维护者通过本仓库的发布流程上传到官方 COS。企业管理员负责部署支持更新接口的服务端；员工点击“检查更新”不会发布版本，也不需要 COS 账号。具体发布步骤见[发行说明](open-source-release.md)。

更新清单尚未发布时，客户端显示“暂无可用的客户端更新”。检查失败时，管理员可查看服务端 `MOSSWORK_HOME/logs/mosswork.log` 中的 `Native update manifest unavailable`；默认路径为 `~/.mosswork/logs/mosswork.log`。访问日志中的 HTTP 状态码不包含具体失败原因。更新接口会区分清单未发布（404）、更新源无法访问（503）和清单无效（502），网络错误响应不包含代理地址或凭据。
